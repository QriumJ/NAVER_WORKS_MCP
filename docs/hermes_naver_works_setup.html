Hermes와 NAVER WORKS를
MCP로 연결하기

컴퓨터 개발을 몰라도 따라 할 수 있도록, 설치부터 테스트·실제 API 연결까지 한 단계씩 설명합니다.

권장 방식: 로컬 stdio MCP: 2026-07-28 읽기 기본 · 쓰기 승인형

0. 먼저 결론

가장 쉬운 순서: Node.js 설치 → 프로젝트 설치 → 연습 모드로 연결 → NAVER WORKS OAuth 토큰 입력 → Hermes에서 자연어로 조회

이 프로그램은 Hermes의 질문을 NAVER WORKS API 요청으로 바꾸는 중간 다리입니다. 현재 MCP에 등록된 Tool은 안전한 읽기 전용이며, 읽기·쓰기·삭제 권한 자체는 Developer Console의 API Key(OAuth Scope)에서 선택합니다.

현재 검수 점수는 98/100입니다. 실계정 호출은 사용자의 조직 권한과 토큰 승인이 필요하므로, 설명서에서는 안전한 mock 연습부터 시작합니다.

1. 어려운 단어를 쉽게 이해하기

Hermes사용자가 자연어로 질문하는 AI 클라이언트입니다. MCP 서버를 등록하면 외부 도구를 사용할 수 있습니다.
MCPAI가 외부 프로그램의 기능을 호출하는 약속입니다. 이 프로젝트는 2026-07-28 규칙을 사용합니다.
NAVER WORKS API일정·주소록·조직 정보를 프로그램으로 읽게 해 주는 공식 통로입니다.
Access Token“이 사용자가 이 정보를 볼 수 있다”는 짧은 수명의 열쇠입니다. 비밀번호처럼 보관하세요.

5. Hermes 채팅으로 설치시키는 지시문

Hermes가 터미널과 파일을 실행할 수 있으면 아래 내용을 그대로 채팅에 붙여 넣으세요. 실행 권한이 없는 Hermes라면 명령만 보여 달라고 한 뒤 위의 단계를 직접 실행합니다.

내 환경을 먼저 확인한 뒤 NAVER WORKS MCP를 설치하고 Hermes에 연결해 줘.

규칙:
1. Windows인지 Ubuntu/Linux인지, Hermes가 Docker 안에서 실행 중인지, 터미널·파일 실행 권한이 있는지 먼저 확인해.
2. Node.js 20.11 이상, npm, Git 설치 여부를 확인해. Docker라면 Node.js 22 이상 이미지를 사용해.
3. 기존 저장소가 있으면 삭제하지 말고 변경사항과 브랜치를 먼저 확인해.
4. 저장소가 없으면 환경에 맞는 명령으로 기본 main을 내려받아:
   git clone https://github.com/QriumJ/NAVER_WORKS_MCP.git NAVER_WORKS_MCP
5. 저장소 폴더에서 npm install과 npm run build를 실행해. Docker라면 Dockerfile 또는 compose.yaml을 사용해.
6. 실제 토큰을 요구하거나 출력하지 말고 NAVER_WORKS_MOCK=true로 npm test를 실행해 22개 테스트를 확인해.
7. Hermes와 MCP가 같은 환경이면 stdio를 사용해. Docker 컨테이너가 분리되어 있으면 compose.yaml의 HTTP 서비스와 서비스 이름 naver-works-mcp를 사용해.
8. HTTP Docker 서비스는 MCP_HOST=0.0.0.0, 32자 이상 MCP_SHARED_SECRET, MCP_ALLOWED_HOSTS에 실제 서비스 이름을 설정하고 외부 공개 시 TLS reverse proxy를 사용해.
9. 설치·빌드·테스트·등록 결과를 단계별로 보고하고, 실패하면 원인과 다음 명령만 알려 줘.
10. Access Token, 비밀번호, 개인정보를 채팅에 출력하거나 Git에 커밋하지 마.
11. 실제 NAVER WORKS 연결은 내가 OAuth 토큰을 준비했다고 말한 뒤에만 진행해. 토큰은 화면에 다시 출력하지 말고 환경 변수나 Secret Manager에만 저장해.
12. API Key Scope는 내가 선택한 권한만 사용해. 기본은 읽기 전용이며, 쓰기·삭제·메시지 전송은 아래의 별도 Tool을 명시적으로 켜고 승인한 경우에만 실행해.
설치 완료 확인: Hermes가 끝났다고 답하면 NAVER WORKS에서 내 프로필을 조회해 줘.라고 말해 보세요. mock-user가 나오면 연결 성공입니다.

6-1-3. 쓰기 Tool 켜기·승인·끄기

쓰기 기능은 기본적으로 꺼져 있어 tools/list에도 나타나지 않습니다. 먼저 Developer Console에서 해당 일반 Scope를 새로 승인하고 Access Token을 다시 발급한 뒤, MCP 프로세스의 환경변수에서 쓰기 기능을 켭니다. 삭제는 한 단계 더 별도 스위치가 필요합니다.

# 공통: .env 또는 Hermes env에 설정
NAVER_WORKS_WRITE_ENABLED=true
# 삭제 Tool까지 노출할 때만 true (평소에는 false)
NAVER_WORKS_DELETE_ENABLED=false

# 필요한 일반 Scope를 read Scope와 함께 지정
NAVER_WORKS_SCOPES=calendar,board,group.note,task,bot.message,bot,calendar.read,board.read,group.note.read,task.read,bot.read,directory.read,contact.read,user.profile.read

# 빌드 후 MCP/Hermes를 완전히 재시작
npm run build
매번 승인: 쓰기 Tool 호출에는 반드시 confirm=true가 필요합니다. Hermes가 실행 전 대상·내용·수신자·삭제 여부를 사용자에게 다시 보여 주고, 사용자가 승인한 경우에만 호출하도록 지시하세요. NAVER_WORKS_WRITE_ENABLED=false로 되돌리면 모든 쓰기 Tool이 즉시 사라집니다. 삭제까지 켰다면 NAVER_WORKS_DELETE_ENABLED=false로 먼저 끄는 것을 권장합니다.

6-2. 콜백 서버를 켜고 NAVER WORKS 로그인

프로젝트 폴더에서 새 터미널을 열고 Client ID만 넣어 콜백 서버를 실행합니다. Client Secret은 이 단계에서 요구하지 않습니다.

Windows PowerShell
$env:NAVER_WORKS_CLIENT_ID="여기에_Client_ID"
$env:NAVER_WORKS_REDIRECT_URI="http://127.0.0.1:8788/callback"
node scripts/oauth-callback.mjs

Ubuntu / Docker 터미널
export NAVER_WORKS_CLIENT_ID="여기에_Client_ID"
export NAVER_WORKS_REDIRECT_URI="http://127.0.0.1:8788/callback"
node scripts/oauth-callback.mjs
서버를 제대로 켠 상태: 터미널에 [oauth] listening at http://127.0.0.1:8788/callback와 로그인 URL이 표시됩니다. 이 콜백 서버는 OAuth 인증 코드를 받는 임시 서버이며, MCP 서버의 http://127.0.0.1:8787/mcp와는 다른 프로그램·포트입니다. 이 단계에서는 MCP_TRANSPORT=http를 설정하지 않습니다.

터미널에 출력된 https://auth.worksmobile.com/... 주소를 브라우저에 붙여 넣고 로그인·동의합니다. 브라우저에 “인증 코드 수신 완료”가 나오면 주소창의 code= 뒤 값만 잠시 복사합니다. state나 전체 URL은 보내지 않습니다.

6-2-1. 콜백 서버 오류가 날 때

증상확인할 것
EADDRINUSE 또는 8788 포트 사용 중기존 콜백 터미널에서 Ctrl+C로 종료한 뒤 다시 실행합니다. 다른 프로그램이 사용 중이면 PowerShell에서 $env:OAUTH_CALLBACK_PORT="8789"를 설정하고 Developer Console Redirect URL도 http://127.0.0.1:8789/callback으로 똑같이 바꿉니다.
브라우저에서 연결할 수 없음127.0.0.1은 콜백 서버와 브라우저가 같은 컴퓨터일 때만 사용합니다. Docker 안에서 서버를 실행하면 호스트에서 접근 가능한 HTTPS Tunnel 주소를 Redirect URL로 등록하고 NAVER_WORKS_REDIRECT_URI에도 완전히 같은 주소를 넣습니다.
유효하지 않은 클라이언트 정보Client ID, Redirect URL, client_id 매개변수를 확인합니다. Developer Console의 Redirect URL과 인증 URL의 redirect_uri는 프로토콜·호스트·포트·경로까지 모두 같아야 합니다.
콜백 후 다시 로그인 화면으로 돌아감한 번 사용한 code를 재사용하지 말고 콜백 서버를 다시 켠 뒤 새 로그인 URL에서 새 code를 발급받습니다.

6-3. Authorization Code를 Access Token으로 교환

Windows PowerShell에서는 아래를 한 번에 붙여 넣습니다. Client Secret은 별표로 입력되고, 토큰 자체는 화면에 출력하지 않습니다.

$code = Read-Host "Authorization Code의 code 값만 입력"
$secret = Read-Host "Client Secret" -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secret)
try { $clientSecret = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr) }

$body = @{
  code          = $code
  grant_type    = "authorization_code"
  client_id     = $env:NAVER_WORKS_CLIENT_ID
  client_secret = $clientSecret
  redirect_uri  = $env:NAVER_WORKS_REDIRECT_URI
}
$tokenResponse = Invoke-RestMethod `
  -Method Post `
  -Uri "https://auth.worksmobile.com/oauth2/v2.0/token" `
  -ContentType "application/x-www-form-urlencoded" `
  -Body $body
if (-not $tokenResponse.access_token) { throw "Access Token이 응답되지 않았습니다." }
"Access Token 발급 성공 · 유효기간: $($tokenResponse.expires_in)초"
$env:NAVER_WORKS_ACCESS_TOKEN = $tokenResponse.access_token

400 오류가 나오면 code가 만료·재사용되었거나 Client ID, Client Secret, Redirect URL 중 하나가 다릅니다. 새 인증 URL을 다시 열어 새 code로 시도하세요. code는 한 번만 사용할 수 있습니다.

6-4. MCP 환경과 Hermes 호스트 수정

프로젝트의 .env를 열어 아래 값을 넣습니다. <발급된 토큰> 부분은 채팅이 아닌 본인 컴퓨터에서 직접 입력합니다. NAVER_WORKS_SCOPES는 API Key에서 선택한 Scope와 맞춰야 하며, 현재 MCP Tool은 아래 읽기 Scope를 사용합니다.

MCP_TRANSPORT=stdio
NAVER_WORKS_MOCK=false
NAVER_WORKS_ACCESS_TOKEN=<발급된 토큰>
NAVER_WORKS_USER_ID=me
NAVER_WORKS_AUTH_MODE=user_oauth
NAVER_WORKS_API_BASE=https://www.worksapis.com/v1.0
NAVER_WORKS_ENFORCE_SCOPES=true
NAVER_WORKS_WRITE_ENABLED=false
NAVER_WORKS_DELETE_ENABLED=false
NAVER_WORKS_SCOPES=calendar.read,directory.read,contact.read,user.profile.read,board.read,group.read,group.note.read,task.read,bot.read,orgunit.read,form.read

Hermes의 MCP 호스트 설정에서 mock 값을 실제 값으로 바꿉니다. Windows 예시는 다음과 같습니다.

{
  "name": "naver-works",
  "command": "node",
  "args": ["C:\\Users\\Home\\Documents\\네이버웍스\\dist\\index.js"],
  "env": {
    "MCP_TRANSPORT": "stdio",
    "NAVER_WORKS_MOCK": "false",
    "NAVER_WORKS_ACCESS_TOKEN": "<토큰을 로컬에서 직접 입력>",
    "NAVER_WORKS_USER_ID": "me",
    "NAVER_WORKS_AUTH_MODE": "user_oauth",
    "NAVER_WORKS_ENFORCE_SCOPES": "true",
    "NAVER_WORKS_SCOPES": "calendar.read,directory.read,contact.read,user.profile.read,board.read,group.read,group.note.read,task.read,bot.read,orgunit.read,form.read"
  }
}

Ubuntu라면 args 경로를 /home/사용자/NAVER_WORKS_MCP/dist/index.js로 바꿉니다. Hermes를 완전히 종료했다가 다시 실행해야 환경 변수가 반영됩니다.

토큰 주의: 값 앞에 Bearer 를 직접 쓰지 않습니다. 서버가 자동으로 붙입니다. Access Token은 24시간 후 만료될 수 있으므로, 만료되면 OAuth 인증부터 다시 진행하세요. API Key에서 쓰기 Scope를 선택해도 현재 MCP의 읽기 전용 Tool이 쓰기 요청을 만들지는 않습니다.

7. Docker에서 Hermes와 연결하기

Hermes와 MCP가 같은 컨테이너면 stdio를 사용합니다. 컨테이너가 두 개면 compose.yaml의 HTTP 서비스와 Docker 서비스 이름으로 연결합니다.

같은 컨테이너: stdio

docker build -t naver-works-mcp:local .
docker run --rm -i --env-file .env naver-works-mcp:local node dist/index.js

-i는 필요하지만 -t는 붙이지 않습니다. MCP stdio는 가상 터미널이 아닌 원시 입출력을 사용합니다.

분리된 컨테이너: HTTP

Windows PowerShell
Copy-Item .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
docker compose up --build

Ubuntu
cp .env.example .env
openssl rand -hex 32
docker compose up --build

.env의 MCP_SHARED_SECRET에 랜덤 문자열을 저장합니다. 분리된 Hermes는 http://naver-works-mcp:8787/mcp와 X-MCP-Shared-Secret 헤더를 사용합니다. Hermes가 MCP 2026-07-28 HTTP envelope를 지원하지 않으면 같은 컨테이너의 stdio를 사용하세요.

9. 안 되면 이 표를 먼저 확인하세요

화면에 보이는 문제해결 방법
node를 찾을 수 없음Windows/Ubuntu에 Node.js 20.11 이상을 설치하거나 Docker Node.js 22 이상 이미지를 사용합니다.
dist/index.js가 없음프로젝트 폴더에서 npm run build를 실행합니다.
토큰이 설정되지 않음.env 또는 Hermes의 환경 변수 칸에 NAVER_WORKS_ACCESS_TOKEN을 넣습니다.
403 또는 Scope 부족Developer Console 권한과 토큰의 Scope를 다시 승인하고 새 토큰을 발급합니다.
mock-user만 계속 표시됨NAVER_WORKS_MOCK=false로 변경하고 Hermes를 재시작합니다.
도구 목록이 비어 있음실행 파일은 node, 인자는 dist\index.js 전체 경로인지 확인합니다.
Docker HTTP가 종료됨MCP_HOST=0.0.0.0, 32자 이상 공유 시크릿, MCP_ALLOWED_HOSTS 서비스 이름을 확인합니다.
컨테이너끼리 연결 안 됨localhost 대신 Compose 서비스 이름 naver-works-mcp를 사용합니다.

10. HTTP 연결은 언제 쓰나요?

다른 컴퓨터의 Hermes가 연결할 때만 선택하세요. 개인 PC에서 Hermes와 MCP를 같이 쓰면 stdio가 더 단순하고 안전합니다.

npm run build
$env:MCP_TRANSPORT="http"
$env:MCP_HOST="127.0.0.1"
$env:MCP_PORT="8787"
node dist/index.js

http://127.0.0.1:8787/healthz가 정상 응답하면 서버가 켜진 것입니다. HTTP /mcp는 MCP 2026-07-28 strict stateless 형식과 표준 헤더를 사용합니다. 인터넷에 바로 공개하지 말고, 원격 운영은 32자 이상 공유 시크릿·Host/Origin 허용 목록·TLS reverse proxy를 함께 사용하세요.
