Hermes와 NAVER WORKS를
MCP로 연결하기

컴퓨터 개발을 몰라도 따라 할 수 있도록, 설치부터 테스트·실제 API 연결까지 한 단계씩 설명합니다.

권장 방식: 로컬 stdio MCP: 2026-07-28 읽기 전용 MVP

0. 먼저 결론

가장 쉬운 순서: Node.js 설치 → 프로젝트 설치 → 연습 모드로 연결 → NAVER WORKS OAuth 토큰 입력 → Hermes에서 자연어로 조회

이 프로그램은 Hermes의 질문을 NAVER WORKS API의 읽기 요청으로 바꾸는 중간 다리입니다. 일정·연락처·구성원은 읽을 수 있지만, 메시지 전송이나 삭제는 하지 않습니다.

현재 검수 점수는 98/100입니다. 실계정 호출은 사용자의 조직 권한과 토큰 승인이 필요하므로, 설명서에서는 안전한 mock 연습부터 시작합니다.

1. 어려운 단어를 쉽게 이해하기

Hermes사용자가 자연어로 질문하는 AI 클라이언트입니다. MCP 서버를 등록하면 외부 도구를 사용할 수 있습니다.
MCPAI가 외부 프로그램의 기능을 호출하는 약속입니다. 이 프로젝트는 2026-07-28 규칙을 사용합니다.
NAVER WORKS API일정·주소록·조직 정보를 프로그램으로 읽게 해 주는 공식 통로입니다.
Access Token“이 사용자가 이 정보를 볼 수 있다”는 짧은 수명의 열쇠입니다. 비밀번호처럼 보관하세요.

확인필요한 것어디서 확인하나요?

3. 처음 연결하기(연습 모드)

  1. 폴더에서 터미널 열기
    GitHub 저장소를 내려받은 폴더에서 PowerShell을 엽니다. 아직 받지 않았다면 아래처럼 완성본 브랜치를 내려받습니다. 
    git clone --branch codex/naver-works-mcp https://github.com/QriumJ/NAVER_WORKS_MCP.git NAVER_WORKS_MCP
Set-Location NAVER_WORKS_MCP
    초안 PR이 main에 병합된 뒤에는 --branch codex/naver-works-mcp를 생략해도 됩니다.
    이미 폴더가 있다면 다음 명령만 실행하세요. 
    npm install
Copy-Item .env.example .env
  2. .env를 연습 모드로 저장
    .env 파일을 메모장으로 열고 아래 세 줄을 넣습니다. 
    MCP_TRANSPORT=stdio
NAVER_WORKS_MOCK=true
NAVER_WORKS_USER_ID=mock-user
  3. 프로그램 만들기와 검사 
    npm run build
npm test
    테스트 결과에 22개 통과가 표시되면 정상입니다.
  4. Hermes에 MCP 서버 추가
    전송 방식은 stdio, 실행 파일은 node, 인자는 아래처럼 입력합니다. 
    {
  "name": "naver-works",
  "command": "node",
  "args": ["C:\\Users\\Home\\Documents\\네이버웍스\\dist\\index.js"],
  "env": {
    "MCP_TRANSPORT": "stdio",
    "NAVER_WORKS_MOCK": "true",
    "NAVER_WORKS_USER_ID": "mock-user"
  }
}
    경로는 실제 폴더의 dist\index.js 전체 경로로 바꾸세요. Hermes 버전에 따라 JSON 대신 입력 칸으로 보일 수 있습니다.
  5. 첫 질문 보내기 
    NAVER WORKS에서 내 프로필을 조회해 줘.
    연습 모드의 예상 결과는 mock-user입니다. 이 응답이 오면 Hermes와 MCP 연결은 완료입니다.

4. Hermes 채팅으로 설치시키는 지시문

Hermes가 터미널과 파일을 실행할 수 있으면 아래 내용을 그대로 채팅에 붙여 넣으세요. 실행 권한이 없는 Hermes라면 명령만 보여 달라고 한 뒤 위의 단계를 직접 실행합니다.

내 Windows PC에 NAVER WORKS MCP를 설치하고 Hermes에 연결해 줘.

규칙:
1. Node.js 20.11 이상, npm, Git 설치 여부를 먼저 확인하고 결과를 알려 줘.
2. C:\Users\Home\Documents\네이버웍스 폴더를 작업 폴더로 사용해. 이미 저장소가 있으면 삭제하지 말고 변경사항과 브랜치를 먼저 확인해.
3. 저장소가 없으면 다음 브랜치를 내려받아:
   git clone --branch codex/naver-works-mcp https://github.com/QriumJ/NAVER_WORKS_MCP.git NAVER_WORKS_MCP
4. 저장소 폴더에서 npm install과 npm run build를 실행해.
5. 실제 토큰을 요구하거나 출력하지 말고 NAVER_WORKS_MOCK=true로 npm test를 실행해 22개 테스트를 확인해.
6. Hermes MCP 서버를 stdio로 등록해. command는 node, args는 dist/index.js 절대 경로, 환경 변수는 MCP_TRANSPORT=stdio와 NAVER_WORKS_MOCK=true로 설정해.
7. 설치·빌드·테스트·등록 결과를 단계별로 보고하고, 실패하면 원인과 다음 명령만 알려 줘.
8. NAVER_WORKS_ACCESS_TOKEN, 비밀번호, 개인정보를 채팅에 출력하거나 Git에 커밋하지 마.
9. 실제 NAVER WORKS 연결은 내가 OAuth 토큰을 준비했다고 말한 뒤에만 진행해. 토큰은 화면에 다시 출력하지 말고 환경 변수나 Secret Manager에만 저장해.
10. 쓰기·삭제·메시지 전송 기능은 추가하지 말고 읽기 전용 도구만 등록해.
설치 완료 확인: Hermes가 끝났다고 답하면 NAVER WORKS에서 내 프로필을 조회해 줘.라고 말해 보세요. mock-user가 나오면 연결 성공입니다.

5. 실제 NAVER WORKS 데이터로 바꾸기

연습이 끝났다면 Developer Console에서 사용자 OAuth 앱을 만들고 다음 읽기 Scope를 승인받습니다.

calendar.read
contact.read
directory.read
user.profile.read

외부 OAuth/Token Provider에서 Access Token을 받은 뒤 .env를 아래처럼 바꿉니다.

MCP_TRANSPORT=stdio
NAVER_WORKS_MOCK=false
NAVER_WORKS_ACCESS_TOKEN=<여기에_짧은_수명의_토큰>
NAVER_WORKS_USER_ID=<조회할_사용자_ID>
NAVER_WORKS_AUTH_MODE=user_oauth
NAVER_WORKS_API_BASE=https://www.worksapis.com/v1.0
NAVER_WORKS_ENFORCE_SCOPES=true
NAVER_WORKS_SCOPES=calendar.read,contact.read,directory.read,user.profile.read
토큰 주의: 값 앞에 Bearer 를 직접 쓰지 않습니다. 서버가 자동으로 붙입니다. 실제 토큰을 넣은 뒤 Hermes를 완전히 종료하고 다시 실행하세요.

6. Hermes에게 이렇게 말해 보세요

프로필“내 NAVER WORKS 프로필을 보여 줘.”
일정“이번 달 내 기본 캘린더 일정을 날짜와 제목만 정리해 줘.”
연락처“연락처에서 김철수를 찾아 줘. 전화번호는 끝 네 자리만 보여 줘.”
조직“우리 조직 구성원을 이름과 부서만 표로 보여 줘.”

서버는 PII(개인정보)를 최소 필드로 제한하고, 연락처 전화번호·이메일은 기본적으로 마스킹합니다.

7. 안 되면 이 표를 먼저 확인하세요

화면에 보이는 문제해결 방법
node를 찾을 수 없음Node.js 20.11 이상 설치 후 Hermes를 다시 시작합니다.
dist/index.js가 없음프로젝트 폴더에서 npm run build를 실행합니다.
토큰이 설정되지 않음.env 또는 Hermes의 환경 변수 칸에 NAVER_WORKS_ACCESS_TOKEN을 넣습니다.
403 또는 Scope 부족Developer Console 권한과 토큰의 Scope를 다시 승인하고 새 토큰을 발급합니다.
mock-user만 계속 표시됨NAVER_WORKS_MOCK=false로 변경하고 Hermes를 재시작합니다.
도구 목록이 비어 있음실행 파일은 node, 인자는 dist\index.js 전체 경로인지 확인합니다.

8. HTTP 연결은 언제 쓰나요?

다른 컴퓨터의 Hermes가 연결할 때만 선택하세요. 개인 PC에서 Hermes와 MCP를 같이 쓰면 stdio가 더 단순하고 안전합니다.

npm run build
$env:MCP_TRANSPORT="http"
$env:MCP_HOST="127.0.0.1"
$env:MCP_PORT="8787"
node dist/index.js

http://127.0.0.1:8787/healthz가 정상 응답하면 서버가 켜진 것입니다. HTTP /mcp는 MCP 2026-07-28 strict stateless 형식과 표준 헤더를 사용합니다. 인터넷에 바로 공개하지 말고, 원격 운영은 32자 이상 공유 시크릿·Host/Origin 허용 목록·TLS reverse proxy를 함께 사용하세요.
